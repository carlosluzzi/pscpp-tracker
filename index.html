# Dossiê — Splash Screen (Claude Quest → aplicar no PSCPP Tracker) ## 1. Problema que isso resolve **No Claude Quest**: ao reabrir o app já logado, aparecia rapidinho a tela de login (email/senha) — às vezes até disparando o Face ID/autofill do Safari — antes da checagem de sessão terminar e finalmente mostrar o app de verdade. Um "flash" incômodo da tela errada. **No PSCPP Tracker**: o problema equivalente não é sessão de login — é o tempo de carregar os dados do Notion. A ideia de fundo é a mesma: uma splash cobre a tela inteira **enquanto o app decide o que mostrar**, evitando qualquer flash de conteúdo errado/incompleto no meio do caminho. ## 2. Detalhes da barra de carregamento (pra ficar idêntico) - O preenchimento tem só **40% da largura** do trilho — não é uma barra que "enche", é um blocão menor que atravessa de um lado a outro - A animação usa `translateX`, não `width` — é deslocamento horizontal do bloco inteiro, não um "encher/esvaziar" - Vai de `-100%` até `350%` (não é 0% a 100%) — o blocão sai **totalmente fora** da caixa de um lado, atravessa, e sai **totalmente fora** do outro lado antes de reiniciar o loop. Por isso o trilho precisa de `overflow:hidden` — sem isso o bloco vazaria visualmente pra fora - `ease-in-out` — acelera no meio, desacelera nas pontas (não é velocidade constante) - `infinite` — nunca para, não tem estado de "concluído" - Cores: trilho `#EEE` (esse pode ficar fixo), preenchimento na **cor de destaque do próprio app** (não é laranja fixo — no Claude Quest é `#D97757` só porque é a cor de marca dele) - Cantos: `border-radius:2px` no trilho e no preenchimento ## 4. Lógica de decisão (a parte mais importante) A splash **já nasce visível** — é a primeira coisa que a pessoa vê sempre, não é algo que aparece depois. A tela de login/conteúdo principal começa **escondida** (`class="hidden"`), e só uma delas é revelada depois que a decisão é tomada. No Claude Quest, a ordem de checagem é: 1. **Primeiro**: veio de link de convite/recuperação de senha? → esconde a splash, mostra a tela de definir senha direto (pula tudo o resto) 2. **Senão**: checa se já existe uma sessão válida salva - **Se tiver**: pula direto pro app — a tela de login **nunca aparece** - **Se não tiver**: esconde a splash, mostra a tela de login normal ```js window.addEventListener('DOMContentLoaded', async ()=>{ // Se veio de link de convite, o Supabase devolve com type=invite no hash da URL if(window.location.hash.includes('type=invite') || window.location.hash.includes('type=recovery')){ document.getElementById('view-splash').classList.add('hidden'); document.getElementById('view-login').classList.remove('hidden'); document.getElementById('login-form-entrar').classList.add('hidden'); document.getElementById('login-form-definir-senha').classList.remove('hidden'); return; } const {data:{session}} = await sb.auth.getSession(); if(session){ await posLogin(); // essa função já esconde a splash e mostra o app direto }else{ document.getElementById('view-splash').classList.add('hidden'); document.getElementById('view-login').classList.remove('hidden'); } }); ``` **No PSCPP Tracker**, a adaptação natural seria trocar o "checa sessão do Supabase" por "espera os dados do Notion carregarem" — mesma estrutura de 3 caminhos (splash → decide → revela a tela certa), só a condição no meio que muda. ## 5. Onde mais a splash precisa ser escondida Qualquer caminho que leve direto pro app (sem passar pela tela de login) também precisa esconder a splash explicitamente. No Claude Quest isso acontece dentro da função que finaliza o login (`posLogin()`): ```js document.getElementById('view-splash').classList.add('hidden'); document.getElementById('view-login').classList.add('hidden'); ```
